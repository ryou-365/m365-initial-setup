# m365-initial-setup

## 目的

本リポジトリは、Microsoft 365 テナントの初期構築において、  
管理センターの GUI 操作に依存しがちな設定作業を **PowerShell Runbook として標準化・可視化**することを目的としています。

単なる設定例やスクリプト集ではなく、

- 誰が構築しても
- どのテナントでも
- 同じ前提・同じ判断・同じ安全性

で **社内リリース可能な Microsoft 365 基盤を再現できること**をゴールとします。

---

## 本リポジトリが重視する考え方

### 1. 実効性の高い「コピペと目視」

本リポジトリでは、スクリプトの一括実行を前提としません。

- コマンドを 1 行ずつ実行
- その場で出力を確認
- 想定外の状態を即座に検知

することで、  
**環境差分・権限不足・設定漏れによる“静かな失敗”を防ぐ**ことを重視しています。

---

### 2. 依存関係を前提とした段階的構築

Microsoft 365 の初期構築には明確な依存関係があります。

- 緊急アクセス未確保でのポリシー適用
- 監査ログ未有効化での構築作業
- セキュリティ既定値の方針未決定のままの設定変更

これらはすべて **後戻りコストを増大させる原因**になります。

本リポジトリでは、

> 実行環境 → ロックアウト耐性 → 監査基盤 → テナント基盤 → 制御強化

という順序を明示し、  
**手戻りのない構築プロセス**を前提としています。

---

### 3. 管理者自身を事故から守る設計

初期構築フェーズは、最も権限が強く、最も変更が集中する期間です。

そのため本リポジトリでは、

- break-glass アカウントの事前確立
- 条件付きアクセスの段階適用（report-only）
- 監査ログを前提とした作業

など、  
**管理者自身をロックアウトや判断ミスから守る設計**を最優先事項としています。

---

## 構成概要と優先度

本リポジトリは、構築フェーズと優先度に基づいた Markdown Runbook で構成されています。  
番号は **実行順序および依存関係**を表します。

### Mandatory（やらないと危険）

以下は、**個社要件に関わらず必ず実施を推奨する設定**です。  
ここまで完了していない状態での社内リリースは想定していません。

#### 00_Initialization  
管理用実行環境のセットアップと、Microsoft Graph / Exchange Online / SharePoint Online / Teams への  
**セキュアで再現性のある接続基盤の確立**。

#### 01_EmergencyAccess  
緊急用（break-glass）アクセスアカウントの作成と、  
**管理者ロックアウト耐性の確立**。

#### 02_AuditAndBaseline  
監査ログを中心とした、  
**構築作業そのものを説明可能にするための証跡基盤の確立**。

#### 03_TenantCoreSettings  
テナント全体に影響する、  
**不可逆・横断的な基本設定（組織情報・通知・既定値方針）の整理**。

---

### Recommended（初期構築として強く推奨）

以下は、**社内リリース前に実施することを強く推奨する設定**です。

#### 04_ConditionalAccessBaseline  
条件付きアクセスを用いた、  
**全体的な認証制御とゼロトラスト設計の適用（段階導入）**。

#### 05_ServiceSecurityBaseline  
Exchange Online を中心とした、  
**認証経路・通信経路・メッセージング環境のセキュリティ強化**。

※ 00〜05 までを完了した状態を、本リポジトリでは  
**「社内リリース可能な初期構築完了状態」**と定義します。

---

### Optional / Optimization（最適化・拡張）

以下は、運用効率化や将来拡張を目的とした設定です。  
初期構築の完了条件には含みません。

- 06_IdentityAndLicenseSetup  
- 07_CollaborationAndStorage  
- 08_DeviceManagementBaseline  
- 90_OptionalOptimizations
